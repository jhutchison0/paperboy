## 3. G4: the determinism probe, stated for a prototyper

**F8 Major. Two runs cannot support the decision, and the API path is not a control.** `docs/gaps.md:14`. If the Agent backend returns a differing output with per-run probability p, two runs agree with probability about (1-p)^2: at p = 0.3 they agree 49 percent of the time, and the register would read that as determinism. The API path at `temperature=0.0` is not a control either: Anthropic's API reference states results at 0.0 are not fully deterministic, so that path's Pillar 4 claim is also an unmeasured assumption. The control is the keyword-only path, deterministic by construction, which proves the harness (fixture, ordering, serialization) before any Claude arm is read. The design:

- **Fixture.** No saved candidate list exists; `select` fetches live. The probe's `--save` step calls `SourceManager.fetch_all()` once and writes the `Paper` list to JSON (ISO dates) under `output/` (gitignored). Every arm and run reads this file with `exclude_ids=set()`, so dedup and sourcing cannot move the universe.
- **Arms.** `keyword-only` (control; any diff across runs means the harness is broken, stop), `api` at temperature 0.0 (`unchecked` with reason when the box has no `ANTHROPIC_API_KEY`; both rostered boxes run `backend: agent`), `agent`.
- **Runs.** k = 10 per arm, same day, same CLI version (`claude --version` recorded). If all 10 agree, the per-run disagreement rate is below 0.26 at 95 percent confidence (1 minus 0.74 to the tenth is 0.95). State that bound in the report; k = 2 bounds nothing useful.
- **Per run, per paper** (the 5 keyword-gated papers; the keyword stage is run once and pinned): paper id, keyword score, Claude score from `_score_with_claude`, combined score recomputed with the config weights, `sha1(reasoning)[:8]`, and a failure flag: `agent_runner.last_error` set after the call, or an exception on the API path. A failed call injects 0.5 on the Agent path (`src/selector.py:257`) and keeps the keyword-only score on the API path (`:126`); a diff caused by a timeout is not non-determinism. Exclude failed runs from the tally and count them.
- **Three surprise tiers.** T1: any Claude score differs (exact comparison; Pillar 4 says same output). T2: the rank order of the five differs. T3: the top-1 differs. T3 decides whether the selection is reproducible; T1 without T3 decides whether the temperature-control task is about score reproducibility only, and the report prints the max score delta beside the top-1 to top-2 margin so a reader sees how close T3 was.
- **Derived line.** For each run, the keyword-weight switch point w* at which the top-2 would swap: w* = (c2 - c1) / ((k1 - k2) + (c2 - c1)). It costs nothing and is the one-at-a-time sensitivity the register has no row for.
- **Report shape.** Rule 8: per arm `checked` with runs, failures, distinct score vectors, distinct rank orders, distinct top-1, max delta, bound; or `unchecked` with a reason and no value key. Written to `docs/reviews/`, never into config or the task list.
- **Docstring.** Universe: the five keyword-gated papers of one fixture. Blind to: the other N-5 candidates, sourcing non-determinism, CLI model drift across days, the distill stage. Ship with a two-shape test and the G4 row's Status pointer.

Rewrite the G4 collector: "A probe that scores one saved candidate list ten times per backend (keyword-only as control, API at 0.0, Agent) and records per-paper Claude scores, rank order, top-1 and failed calls; design in `docs/reviews/20261022_gap_register_ds_review.md` section 3."

## 4. G3: the listening test

**F9 Major. One episode per arm cannot separate the kernel from NotebookLM's own variance.** NotebookLM generates a different episode from the same briefing each time, so a single pair confounds the prompt effect with generation noise. Design:

- **Pairing.** Same paper (arXiv:2607.16131), two briefings already on disk (pre-kernel, 49 em dashes; kernel, 0). Generate two episodes per briefing on the same day: four episodes, about two hours. The within-arm pair is the noise floor; a between-arm difference smaller than it is nothing.
- **Blinding.** The listener wrote the kernel and cannot be blind to content. Blind the order: a coin flip assigns A and B per pair, the assignment is written to a file and not read until the form is filled. A second listener who has read neither briefing is better evidence and the only route to real blinding.
- **The form, filled at the end of each episode, not later.** A tally kept during listening of moments the listener lost the thread or rewound (count, exact); three ratings on 1 to 5 for host delivery (stumbles, pace), clarity (can the listener restate the core idea), and structure (how many of the 8 sections were recognisable, 0 to 8); and per pair one forced choice, which episode they would want in the feed.
- **How many before a verdict.** A sign test on paired forced choices needs 5 of 5 pairs one way to reach p = 0.031; 4 of 4 gives 0.0625 and decides nothing. So a statistical verdict needs five papers, ten episodes, about five hours. The decision does not need that. The text metrics already favour the kernel, so the listening test's job is to detect harm, not confirm benefit. Decision rule: the kernel stays unless the pre-kernel episode wins both pairs on the first paper; only then expand to five papers.
- **What it cannot show.** Whether the audible difference comes from the prose rules or from length (4,945 vs 4,615 words; a shorter briefing paces differently); anything about papers or listeners beyond the one tested; whether em dashes matter at all (NotebookLM reads text; the count is a proxy for the discipline, not an audible cause); and NotebookLM version drift if the arms are generated on different days.

Rewrite the G3 collector: "The listening test (owner distiller-dev): two NotebookLM episodes per briefing from the kernel-styled and pre-kernel versions of one paper, order blinded by a sealed coin flip, each episode scored on a fixed form (lost-thread tally, three 1-to-5 ratings, one forced choice per pair), recorded in `docs/reviews/`. The kernel reverts only if the pre-kernel arm wins both pairs."

## 5. G6: cadence against horizon

**F10 Minor. `/session-start` is the right instrument for the stated decision; the surprise must be per feed, and `health_check()` is the wrong probe.** The decision is read at session start, so a measurement there is current for the only reader it has; the gaps between sessions (up to two months in `docs/sessions/`) violate no horizon because no decision reads the line then. The Phase 3 pipeline run is a different reader with its own horizon; when it exists, it emits the same per-feed line into its run log and a new row supersedes G6. Name one collector, not "or". The surprise is per feed and depends on cadence: zero articles in seven days from Lilian Weng is expected, zero from Google Research is not. Until four weekly baselines exist, use the cadence-free surprises in F5 (a warning, zero total entries, newest entry older than 90 days). `BlogSourcer.health_check()` (`src/sourcer.py:256`) returns True if any one feed has entries: four feeds collapsed to one bit that is true with three dead, a rule 8 violation; do not use it. A full `python main.py source` also fetches four arXiv categories at a 3-second rate limit for no information about feeds; a feed-only listing is the cheaper instrument.

## 7. The weights: what is a gap and what is not

`keyword_weight` 0.4 and `claude_weight` 0.6 sum to 1.0, are non-negative, and combine two [0, 1] utilities; `config.validate` pins the sum (warning, not error, at `src/config.py:272`). The weights are valid inputs and are not a gap. Three things around them are defects for the task list, and two are gaps the register should hold.

**F14 Major. The category sub-criterion is structurally zero.** `src/selector.py:184-192`. Measured 2026-10-22 against the checked-in config: 0 of 25 keywords match `cs.ai cs.lg cs.cl stat.ml`, and 0 match any feed name (articles carry their source as their only category). So `category_score` is 0 for every candidate, the keyword score's ceiling is 0.85, and the combined ceiling is 0.94. The declared 0.50/0.35/0.15 is in effect 0.59/0.41, and the declared 0.4/0.6 is in effect 0.36/0.64. Ranking is unharmed (the shift is uniform) but the documented model does not describe the live one. A task: drop the criterion and re-normalize to 0.59/0.41, or give it a universe it can hit, and move the three sub-weights to `config/paperboy.yaml`.

**F15 Minor. Failure is scored differently on the two backends.** An API-path exception keeps the keyword-only score, up to 0.85 uncombined (`src/selector.py:126`); an Agent-path failure injects 0.5 (`:257`), so combined is 0.4k + 0.3. A paper whose call failed competes on a different scale from its neighbours and, on the API path, is rewarded for failing. A task; and the reason the G4 probe must count failures (section 3).

**F16 Minor. `min_score_threshold` has no effect on the pipeline's selection.** With `top_k=1` and the fall-back to the top candidate (`src/selector.py:139-144`), the threshold only shapes the `select` CLI's top-5 listing. Not a gap; document it, or remove the fall-back if the threshold is meant to bite.

**F17 Major. Two gaps the register should hold.** The register has zero outcome lines; every row is an input (`DOCTRINE.md`, the MOP and MOE row). Nothing observes whether the gate or the weights select well. Proposed rows:

| G7 | Whether the keyword gate (`top_k_for_claude` 5 of the day's N candidates) passes the paper the Claude stage would rank first. The gate is a keyword-only decision over N minus 5 candidates and nothing has observed what it excludes. | A probe that Claude-scores the top 20 by keyword on one saved candidate list and records the keyword rank of Claude's top-1 (an integer 1 to 20, exact); surprise: rank above 5. Blind to candidates below keyword rank 20. | Whether `top_k_for_claude` stays at 5 or rises, and so whether the batch-scoring task is needed to pay for it. | 2026-10-22 | open |
| G8 | Whether the selected paper is the one the reader would have chosen from the day's top 5. No outcome measure exists for selection. | A one-line verdict per briefing from the reader (`agree`, or the rank they would have picked, 1 to 5) recorded with its date beside the selection history; shape: a rank, exact; agreements of N days. | Whether `keyword_weight` and `claude_weight` are retuned at all: at 4 agreements of 5 or better the weights are not the bottleneck. | 2026-10-22 | open |

## Verdict

The register is a real register: six known unknowns, each with a collector and a two-outcome decision, none a defect in disguise, and the test pins the two required fields. It is not yet a sound one, because three collectors would close their gap on the wrong quantity (G2 measures log coverage, G5 misreads a clone that is behind, G6 misses a feed that dies quietly), G4 as written would call a 30-percent-flaky backend deterministic half the time, and the G3 listening test as scoped cannot tell the kernel from NotebookLM's noise. The fixes are rewrites of cells and one probe design, not new doctrine. The weights themselves pass; the dead category sub-criterion (F14) is the one scoring defect, and the absence of any outcome line (F17) is the one decision-science gap the register should open before it closes anything.
